Relacionales No relacionales
Es como organizar todo en tablas de Excel, puras filas y columnas bien ordenadas que se conectan entre sí mediante llaves (IDs). Aquí las cosas son estrictas: antes de meter datos, tienes que definir exactamente qué tipo de información va a ir en cada columna (números, textos, fechas). Son ideales cuando manejas datos que deben estar súper estructurados y relacionados, como las cuentas de usuarios o transacciones de dinero. Es más libre, funciona como cajas o documentos independientes (por ejemplo, formato JSON). No necesitas crear tablas rígidas ni planear una estructura fija desde antes; puedes guardar información diferente en cada registro sin que te marque error. Son perfectas cuando manejas volúmenes grandes de datos que cambian constantemente o que no tienen una forma fija.

Buenas prácticas en PosgreSQL
  • Se recomienda no crear bases de datos ni objetos en public
  • Se debe crear una nueva base de datos y en ella un nuevo esquema para insertar tablas
  • PosgreSQL usa minúsculas principalmente, es recomendado evitar usar mayúsculas por si después se necesita migrar la base de datos a otro gestor
  • Los nombres de las tablas es en plural, los nombres de los campos en singular
  • Se debe planear bien las tablas, no agregando campos innecesarios para no hacerlas demasiado grandes lateralmente
  • De manera preferente se debe hacer un nuevo registro en vez de actualizar o eliminar un registro anterior
Jerarquía de una base de datos
  • Los servidores son los containers principales de la base de datos, hace referencia al gestor de la base, no a la base en si
  • Cada servidor puede tener n numero de puertos, nos ayuda a enlazarnos al servicio de la base de datos
  • Cada puerto puede tener varias bases de datos
  • Cada base de datos puede tener varios esquemas
  • Cada esquema puede tener varias tablas y estas a su vez varias columnas
